NOMADNEST DEPLOYMENT GUIDE
===========================

This project has two separate applications:

1. client/ - React + Vite frontend
2. server/ - Express + MongoDB API

Recommended production setup:

- MongoDB Atlas for the database
- Render or Railway for the Express backend
- Netlify OR Vercel for the React frontend

Netlify and Vercel are excellent for the Vite frontend. The current Express server is a normal long-running Node server, so it should be deployed to a Node backend host instead of being uploaded as a static frontend.


PART 1 - PREPARE THE PROJECT
============================

1. Push the project to GitHub

   From the project root:

   git init
   git add .
   git commit -m "Prepare project for deployment"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
   git push -u origin main

   Do not commit server/.env. Confirm that .env is in .gitignore.

2. Rotate exposed secrets

   The local server/.env contains database and JWT values. If that file was ever pushed to GitHub or shared, immediately:

   - Create a new MongoDB database password.
   - Create a new JWT secret of at least 32 characters.
   - Remove the old secrets from Git history if they were committed.

3. Create a MongoDB Atlas database

   a. Open https://www.mongodb.com/atlas/database
   b. Create an account or sign in.
   c. Create a free M0 cluster.
   d. Create a database user and password.
   e. In Network Access, add the IP access required by your backend host.
      For initial testing, 0.0.0.0/0 allows access from anywhere, but restrict this later if your host provides fixed outbound IPs.
   f. Select Connect > Drivers and copy the MongoDB connection string.
   g. Replace the password placeholder in the connection string.


PART 2 - REQUIRED FRONTEND API CHANGE
=====================================

The current client uses baseURL: '/api'. That works only with the local Vite proxy. In production, the frontend must call the deployed backend URL.

Open:

client/src/services/api.js

Replace:

const api = axios.create({
  baseURL: '/api',
  headers: { 'Content-Type': 'application/json' },
  timeout: 15000,
});

With:

const api = axios.create({
  baseURL: `${import.meta.env.VITE_API_URL || ''}/api`,
  headers: { 'Content-Type': 'application/json' },
  timeout: 15000,
});

The production frontend environment variable must contain only the backend origin, without /api at the end.

Correct:

VITE_API_URL=https://your-backend.onrender.com

Incorrect:

VITE_API_URL=https://your-backend.onrender.com/api

Commit and push this change:

   git add client/src/services/api.js
   git commit -m "Configure production API URL"
   git push


PART 3 - DEPLOY THE BACKEND API
================================

Use Render or Railway for the backend. The following example uses Render.

1. Open https://render.com and sign in with GitHub.
2. Select New > Web Service.
3. Select the GitHub repository.
4. Configure the service:

   Name: nomadnest-api
   Root Directory: server
   Runtime: Node
   Build Command: npm install
   Start Command: npm start
   Instance Type: Free or a suitable paid plan

5. Add these environment variables in the Render Environment settings:

   NODE_ENV=production
   PORT=10000
   MONGO_URI=YOUR_MONGODB_ATLAS_CONNECTION_STRING
   JWT_SECRET=YOUR_NEW_RANDOM_SECRET_AT_LEAST_32_CHARACTERS
   CLIENT_URL=https://YOUR_FRONTEND_DOMAIN

   Do not add quotes around the values.
   Set CLIENT_URL to the final Netlify or Vercel URL. It can be updated after the frontend is deployed.

6. Deploy the service.
7. Copy the public backend URL. It will look similar to:

   https://nomadnest-api.onrender.com

8. Test the API health endpoint in a browser:

   https://nomadnest-api.onrender.com/api/health

   A successful response contains success: true.

9. Optional: seed the production database.

   In the backend host's shell or one-time command feature, run:

   npm run seed

   Run the seed command only once against a new database. Do not run it against a production database that already contains user or booking data unless you have verified what the seed script changes.

If using Railway instead:

- Create a new project from the GitHub repository.
- Set the service root directory to server if prompted.
- Build command: npm install
- Start command: npm start
- Add the same environment variables listed above.
- Copy the generated public domain and test /api/health.


PART 4A - DEPLOY THE FRONTEND TO NETLIFY
=========================================

1. Open https://app.netlify.com and sign in with GitHub.
2. Select Add new site > Import an existing project.
3. Choose GitHub and select the repository.
4. Configure the build:

   Base directory: client
   Build command: npm run build
   Publish directory: client/dist

   If Netlify interprets the base directory automatically, use:

   Base directory: client
   Build command: npm run build
   Publish directory: dist

5. Add this environment variable under Site configuration > Environment variables:

   Key: VITE_API_URL
   Value: https://YOUR_BACKEND_HOST

   Example:

   VITE_API_URL=https://nomadnest-api.onrender.com

6. Select Deploy site.
7. Copy the Netlify URL, for example:

   https://your-site-name.netlify.app

8. Return to the backend host and change:

   CLIENT_URL=https://your-site-name.netlify.app

9. Redeploy the backend after changing CLIENT_URL.
10. Trigger a new Netlify deploy after changing any frontend environment variable.

SPA refresh support for React Router:

Create this file:

client/public/_redirects

with this one line:

/*    /index.html   200

Commit and push it before deploying, or redeploy after adding it. This prevents a direct refresh of /rooms, /login, or another React route from returning a 404.


PART 4B - DEPLOY THE FRONTEND TO VERCEL
=======================================

1. Open https://vercel.com and sign in with GitHub.
2. Select Add New > Project.
3. Import the GitHub repository.
4. Configure the project:

   Framework Preset: Vite
   Root Directory: client
   Build Command: npm run build
   Output Directory: dist
   Install Command: npm install

5. Add this environment variable before deploying:

   Key: VITE_API_URL
   Value: https://YOUR_BACKEND_HOST

   Example:

   VITE_API_URL=https://nomadnest-api.onrender.com

6. Select Deploy.
7. Copy the Vercel URL, for example:

   https://your-project.vercel.app

8. Return to the backend host and set:

   CLIENT_URL=https://your-project.vercel.app

9. Redeploy the backend after changing CLIENT_URL.
10. Redeploy the Vercel project after changing frontend environment variables.

React Router history fallback:

Vercel normally handles SPA routes for a Vite deployment. If refreshing a route returns 404, create client/vercel.json with:

{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}

Commit and redeploy after adding the file.


PART 5 - FINAL TEST CHECKLIST
=============================

1. Open the deployed frontend URL.
2. Open the browser developer tools and confirm API requests go to:

   https://YOUR_BACKEND_HOST/api/...

3. Confirm these work:

   - Landing page loads.
   - Rooms page loads room data from the API.
   - A new guest can register.
   - A guest can log in.
   - A guest can create and view a booking.
   - Refreshing /rooms and /login does not show a 404.
   - Admin or staff login works if the database was seeded.

4. Test the backend directly:

   https://YOUR_BACKEND_HOST/api/health

5. If the browser reports a CORS error:

   - Check that CLIENT_URL exactly matches the frontend URL.
   - Do not add a trailing slash unless the deployed URL includes one.
   - Redeploy the backend after editing CLIENT_URL.

6. If the frontend reports Network Error or requests use localhost:

   - Check VITE_API_URL in the frontend host settings.
   - Confirm client/src/services/api.js uses import.meta.env.VITE_API_URL.
   - Trigger a fresh frontend deployment.

7. If the backend cannot connect to MongoDB:

   - Check MONGO_URI.
   - Check the Atlas database username and password.
   - Check Atlas Network Access.
   - Check the backend deployment logs.


PART 6 - ENVIRONMENT VARIABLE SUMMARY
======================================

Backend host variables:

NODE_ENV=production
PORT=10000
MONGO_URI=mongodb+srv://...
JWT_SECRET=long-random-production-secret
CLIENT_URL=https://your-site.netlify.app

Frontend host variable:

VITE_API_URL=https://your-backend.onrender.com

Never place MONGO_URI or JWT_SECRET in the frontend. Never use VITE_ for secrets because Vite exposes VITE_ variables in the browser bundle.


WHICH OPTION SHOULD YOU USE?
=============================

Use Netlify when you want a simple static frontend deployment with an easy deploy preview workflow.

Use Vercel when you want Git-based frontend deployments and convenient preview environments.

For this repository, both options use the same backend setup. Deploy the frontend to only one of them unless you specifically want two separate live frontend environments.
